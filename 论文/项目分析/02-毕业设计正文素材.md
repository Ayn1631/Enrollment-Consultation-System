# 毕业设计正文素材

以下内容按论文正文常见写法整理，已经尽量贴近当前代码实现，可直接改写后纳入“系统分析”“总体设计”“关键技术实现”“系统测试”等章节。

## 1. 系统概述

本系统面向高校招生咨询场景，设计并实现了一套融合检索增强生成、结构化知识查询、会话记忆管理和专家模式编排的智能问答系统。系统围绕招生章程、招生专业、录取分数线、学费资助、报到流程等高频咨询问题，构建了以本地知识库和结构化招生数据为核心、以证据约束为原则的问答流程。

与传统 FAQ 系统相比，本系统能够支持自然语言提问、多轮追问、流式响应和多能力协同处理；与纯生成式聊天机器人相比，本系统更加重视答案依据与风险控制，通过混合检索、引用校验、质量闸门、失败降级和安全审查等机制，尽量降低大模型幻觉对招生咨询场景造成的误导风险。

## 2. 系统总体架构设计

系统采用前后端分离架构。前端基于 Vue 3 构建单页应用，负责用户输入、消息展示、模式切换、流式响应消费以及运维交互；后端基于 FastAPI 提供统一 API 接口，并在内部通过网关编排器组织 RAG 检索、结构化查询、技能执行、记忆调用和文本生成等能力模块。

从逻辑上看，系统可划分为表现层、接入层、编排层、能力层和数据层五个层次。表现层负责与用户交互；接入层负责请求接收、参数校验、健康检查和流式输出；编排层负责问题路由、执行计划和降级控制；能力层负责检索、记忆、技能和生成；数据层负责存放招生原始资料、向量索引、结构化表和可选图谱数据。该架构兼顾了系统的可维护性、可扩展性与可观测性。

## 3. 前端设计

前端采用 Vue 3、TypeScript 和 Vite 技术栈实现。选择 Vue 3 的主要原因在于其组件化开发方式清晰，适合构建以对话交互为核心的单页界面；TypeScript 有助于增强消息对象、健康状态、流式事件和接口契约的类型安全；Vite 则能够提供较快的开发反馈与构建效率。

在界面组织上，系统包含左侧会话栏、中间对话区和右侧运维面板三部分。用户可以在普通对话模式、RAG 问答模式和专家模式之间切换。右侧面板不仅用于调整模型参数和专家策略，还可以显示系统健康状态、触发索引重建和执行上下文压缩。因此，前端不仅承担了“输入输出展示”职责，也承担了系统运行状态可视化的作用。

## 4. 后端设计

后端以 FastAPI 为核心服务框架，提供聊天接口、流式聊天接口、功能元数据接口、历史技能接口、记忆压缩接口、健康检查接口以及索引重建接口。FastAPI 与 Pydantic 结合后，使请求模型、流式回传结构和管理接口返回值均具有明确的类型约束，有利于保证系统接口的一致性。

在系统结构上，后端并未将全部业务逻辑直接写入控制器，而是通过网关编排器统一处理输入审查、Query Router 路由、特性规划、记忆接入、RAG 调用、结构化查询、技能执行和答案生成。该设计降低了控制器复杂度，也使不同能力模块之间的调用关系更加清晰。

## 5. RAG 检索增强设计

本系统的 RAG 设计不是简单的“向量检索加大模型生成”，而是围绕招生场景构建了一条较为工程化的检索链路。系统首先对用户问题进行标准化和查询路由，再结合会话记忆做查询改写，并生成适合检索的候选查询；随后同时执行稠密检索、BM25 稀疏检索和关键词精确匹配，并使用 RRF 融合多路结果；在得到候选证据后，再通过重排器优化排序，之后执行冲突裁决、覆盖度检查、时效性检查、二次检索重试和引用校验，最后再拼装为供生成模块使用的上下文。

在索引实现上，系统采用 FAISS 作为本地向量索引，并构建了索引清单文件来校验语料是否发生变化，避免加载陈旧索引。对于无法使用远程 Embedding 或 Rerank 服务的情况，系统还提供本地向量化和启发式重排保底逻辑，以保证在实验环境不稳定时系统仍可运行。这种设计体现了对实际部署条件和教学项目演示场景的充分考虑。

## 6. 结构化知识查询设计

招生咨询问题中存在大量字段约束明确的问题，例如“某专业学费是多少”“某省某专业录取分数线是多少”“某专业选考科目要求是什么”。若仅使用非结构化文档检索，容易出现字段提取不准、数值回答不稳定的问题。因此，本系统设计了结构化招生知识查询模块，并将专业目录、录取分数线、政策附表、FAQ 种子数据等内容沉淀到 MySQL 表中。

在处理流程上，系统首先根据关键词识别问题类型，并自动路由到专业目录查询、分数线查询或政策附表查询工具。当数据库不可用或无结果时，还会回退到本地缓存文件执行相似检索，从而提高结构化查询链路的可用性。该模块有效增强了系统在费用、学制、位次、选科、专业代码等场景下的回答准确性。

## 7. 专家模式与工作流设计

专家模式是本系统区别于普通问答模式的重要特征之一。其设计目标并不是让系统“看起来更智能”，而是通过显式的工作流编排机制，把复杂问题拆解成更容易求解的子问题，再分别执行检索、技能调用、记忆承接与结果合成。

在实现上，专家模式由 Agent Graph 驱动。系统会先加载短期记忆、长期记忆和特殊记忆，再对当前问题执行前处理、查询改写和意图路由；对于复合问题，会进一步拆分子问题，并为每个子问题生成计划步骤；系统随后并行执行这些步骤，并根据执行结果决定是否重试或重规划；当子问题结果收集完成后，再统一生成最终回答并将步骤事件通过 SSE 回放给前端。与此同时，系统还提供“速度优先”和“质量优先”两种策略，前者更强调响应时延，后者允许更多次重试和一次重规划，以换取更高的回答完整性。

需要说明的是，专家模式虽然支持接入 MCP 工具运行时，并在前端预留了更丰富的特性开关，但当前稳定主链路仍以本地 RAG、结构化查询、记忆和技能机制为主。因此，在论文中应将专家模式表述为“多能力编排型问答流程”，而不宜夸大为完全自治的联网智能体。

## 8. 会话记忆与技能机制设计

为改善多轮问答体验，系统设计了短期记忆、长期记忆和特殊记忆三类机制。短期记忆用于保持当前会话中最近轮次的重要上下文；长期记忆通过滚动摘要方式记录用户持续关注的问题和已形成的结论；特殊记忆则用于保存用户的长期偏好，例如偏好简短回答、偏好分点说明等。记忆既会参与查询改写，也会参与最终回答生成，从而提升追问场景下的上下文承接能力。

在技能机制方面，系统支持通用技能执行和保存技能调用。保存技能具备版本号、内容哈希去重和自动激活最优版本等能力，可作为后续专题助手扩展的基础。当前技能实现仍偏规则化和模板化，更适合作为“领域流程封装能力”来描述，而不是强行解释为完全自治的智能技能学习系统。

## 9. 系统可靠性与保底措施

考虑到招生咨询涉及费用、流程、政策和时间节点等高谨慎信息，本系统在可靠性方面做了较多工程设计。首先，系统通过 `IsolationExecutor` 对 RAG、记忆、技能等依赖能力统一执行隔离保护，当某能力连续失败达到阈值后会暂时打开熔断，避免重复调用导致整体性能恶化。其次，系统使用 `CitationGuard` 和 `RetrievalQualityGate` 对召回证据的来源数量、覆盖度、时效性和冲突情况进行检查，在证据不足时主动降级，而不是强行输出确定性结论。

此外，系统还实现了多层保底逻辑。例如，当 Rerank 服务不可用时，系统会回退到启发式重排；当 FAISS 或远程 Embedding 不可用时，系统会使用本地向量化和相似度计算继续完成检索；当结构化数据库不可用时，会回退到本地缓存文件；对于“院长是谁”“联系方式是什么”等精确事实问题，在 RAG 低分降级情况下还会尝试本地文档精确扫描补救。专家模式在最终生成阶段超时时，也不会伪装成已正常回答，而是给出基于已完成步骤的保守汇总。这些设计共同构成了系统的保底措施。

## 10. 安全审查设计

为防止模型或用户请求泄露内部信息，系统在输入和输出两个方向都设置了安全审查机制。对于“输出系统提示词”“忽略规则”等明显越权请求，系统会直接拦截并返回业务引导；对于生成结果中出现“system prompt”“developer message”或疑似密钥片段等敏感内容，系统也会进行输出拦截与替换。该机制虽然简单，但在毕业设计中已经足以体现对大模型安全边界的基本考虑。

## 11. 测试与评测设计

系统测试分为三层。第一层是前后端单元与集成测试，前端使用 Vitest 验证请求构造、消息渲染和右面板逻辑，后端使用 pytest 覆盖 API、RAG、结构化工具、专家模式、熔断并发和服务应用等模块。第二层是评测脚本，通过构造普通问题、时效问题、技能降级问题和生成失败问题，对网关回答能力进行量化评估，并统计通过率、引用命中率和 P95 延迟等指标。第三层是发布门禁脚本，根据评测报告判断当前版本是否允许推进到下一阶段，并检查相对基线是否出现明显回归。

这种“测试 + 评测 + 门禁”的设计使项目不仅具备功能实现，还形成了基本的工程质量闭环。

## 12. 存在的问题与改进方向

虽然系统已经形成较完整的原型，但仍存在进一步优化空间。首先，当前记忆主要保存在进程内内存中，尚不支持多实例共享和长期持久化；其次，Docker Compose 中预留的 PostgreSQL/pgvector 和 Redis 容器尚未完全接入现有主链路；再次，专家模式下的外部 MCP 工具能力受配置和运行环境影响较大，当前应视为扩展能力而非稳定默认能力；最后，技能机制和知识图谱增强仍有较大深化空间，后续可在动态规划能力、图谱构建质量和跨轮决策支持方面继续完善。

## 13. 小结

综上所述，本系统围绕高校招生咨询这一高谨慎垂直场景，构建了一个以本地知识库、结构化招生数据和可编排问答流程为核心的智能咨询平台。系统的主要价值不在于单纯叠加模型能力，而在于把检索增强、结构化查询、记忆承接、专家模式编排、故障降级和工程质量控制结合起来，从而使系统不仅“能回答”，而且“尽量答得稳、答得准、答得有边界”。这一特点也使其具备较好的毕业设计研究价值和系统设计分析价值。
