## 8. 当前实现与预留设计的边界

| 项目 | 当前状态 | 说明 |
| --- | --- | --- |
| FAISS | 已形成主链路 | 当前主向量检索实现 |
| BM25 | 已形成主链路 | 当前主稀疏检索实现 |
| MySQL | 已形成主链路 | 当前结构化招生库真实落点 |
| Neo4j | 可选增强 | 配置齐全时才参与上下文构建 |
| MCP 外部工具 | 可扩展能力 | 是否可用取决于 MCP 配置和环境 |
| `web_search` 前端标记 | 受控预留 | 当前后端受控工具目录未把它当默认稳定本地工具公开 |
| Redis | 部署预留 | Compose 中存在，但主业务代码未形成明确稳定读写闭环 |
| PostgreSQL/pgvector | 部署预留 | Compose 中存在，但当前主链路未实际使用 |
| 记忆持久化 | MVP 级 | 当前主要为进程内内存，不是分布式持久化 |

## 9. 论文写作建议

1. 已经进入主代码链路的技术，可以直接写“采用了”。
2. 仅在 Compose、配置或可选适配层中出现的能力，建议写成“预留”或“支持扩展到”。
3. 专家模式建议写成“多能力编排式问答流程”，不要直接写“稳定联网自治代理”。
4. 系统亮点建议优先强调混合检索、结构化查询、降级链、安全审查和测试门禁，不要把重点放在模型名称堆砌上。
